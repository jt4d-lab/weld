# Метаданные файла в `weld inspect`

## Цель

Дополнить `weld inspect <file>` именем модуля, именем слоя и путем внутри модуля и слоя. Определение
метаданных сделать общим для CLI и будущего правила направления зависимостей и видимости модулей.
Само правило в эту работу не входит.

## Контекст

- `src/settings/` читает и валидирует `settings.weld`, поддерживает одноименные опции правил и
  кэширует успешный разбор алиасов.
- `src/config/` предоставляет ленивый резолв настроек; `src/rules/context.ts` адаптирует его для
  правил.
- `src/cli/inspect.ts`, `src/cli/program.ts` и `src/cli/render.ts` собирают и выводят путь файла и
  алиас. `src/cli/eslint-config.ts` выбирает опции первого правила `weld/*` с объектом опций.
- Операции над виртуальными путями находятся в `src/path/`; тесты лежат рядом с кодом. Упакованный
  CLI проверяется через `scripts/smoke-test.sh`.
- Проект использует Yarn 4, TypeScript, ESLint и Vitest. Команды проверки — `yarn test`,
  `yarn verify`, `yarn smoke`.

## Решение

### Настройки схемы

Добавить настройки `srcDir`, `modulesDir`, `layers`, `moduleLayers` в `settings.weld` и одноименные
опции правил. Каждая опция целиком переопределяет соответствующую настройку.

- `srcDir` — путь от корня репозитория, по умолчанию `src`. Нормализуется в виртуальный путь; выход
  выше корня — ошибка. `.` означает корень репозитория.
- `modulesDir` — имя директории-контейнера, по умолчанию `modules`. Используется внутри `srcDir` и
  внутри каждого модуля. Это один непустой сегмент без `/`, `\`, `@`, `:`; `.` и `..` не являются
  именами директорий. Точка внутри имени разрешена.
- `layers` — упорядоченные слои проекта и маркеры `@modules`, `@unknown`.
- `moduleLayers` — обязательные упорядоченные слои модулей. Для них в `layers` требуется маркер
  `@modules`.
- Отсутствие `layers` или `moduleLayers` и пустой массив в любом из них — ошибки при запросе схемы.
  Обычное имя слоя начинается с буквы, далее допускаются буквы, цифры, `.`, `-`, `_`. Маркеры
  допустимы только в `layers`, каждый не более одного раза. Обычное имя не может совпадать с
  `modulesDir` или встречаться в обоих списках.
- Повторы обычных имен разрешены и сохраняются в исходном порядке для будущего сравнения диапазонов
  слоев.
- Ошибки явной конфигурации на английском. Источник значения (`settings.weld` или `options`)
  указывается, если это не усложняет код. Успешный разбор кэшируется с TTL по образцу алиасов;
  ошибки не кэшируются.

Чтение и валидация остаются в `src/settings/`. `src/config/` предоставляет ленивый `getScheme()`:
при его вызове отсутствие или некорректность схемы вызывают ошибку. Простое создание резолва и
работа правила, которому схема не нужна, ее не проверяют. Правилу схема доступна лениво. ESLint
проверяет `meta.schema` до вызова правила и при расчете конфига, поэтому схема ESLint для четырех
новых опций должна допускать любые значения; их валидация выполняется при запросе схемы WELD.

### Метаданные

Новый слой `src/layers/` работает с виртуальным путем и разобранной схемой, без доступа к диску и
ESLint. Его публичный интерфейс включает `FileMeta`, функцию определения метаданных и преобразование
цепочки модулей в отображаемое имя.

`FileMeta` содержит:

- `module` — цепочку имен модулей; пустая цепочка выводится как `@root`;
- `layer` — имя слоя либо `@unknown`, если слой не определен;
- `innerPath` — путь относительно корня слоя, а при `@unknown` — относительно корня модуля или
  `srcDir` для `@root`.

Имена модулей хранятся цепочкой, не строкой: будущее правило сравнивает цепочки. При выводе
`['billing', 'subscription']` превращается в `billing::subscription`. В именах всех файлов и
директорий внутри `srcDir` запрещены `@` и `:`; точки разрешены. Это проверяется при определении
метаданных, а не при создании резолва. Сегменты самого пути `srcDir` к этой проверке не относятся.
Принадлежность к слою определяется первым сегментом директории от корня проекта или модуля; глубже
слой не ищется. Последний сегмент пути файла не является директорией ни модуля, ни слоя.

Код без слоя проекта получает `@unknown`, даже если этот маркер отсутствует в схеме. `inspect`
показывает метаданные; будущее правило определит нарушение по модулю и схеме. Внутри модуля
`@unknown` обозначает ветку ниже всех его слоев. Путь вне `srcDir` не имеет метаданных и вызывает
ошибку `inspect`.

Примеры при `srcDir: 'src'`, `modulesDir: 'modules'`, слое проекта `app` и слое модуля `features`:

| Файл                                                         | Модуль                  | Слой       | `innerPath`         |
| ------------------------------------------------------------ | ----------------------- | ---------- | ------------------- |
| `src/app/nested/pages/x.ts`                                  | `@root`                 | `app`      | `nested/pages/x.ts` |
| `src/utils/format.ts`                                        | `@root`                 | `@unknown` | `utils/format.ts`   |
| `src/modules/billing/features/panel.ts`                      | `billing`               | `features` | `panel.ts`          |
| `src/modules/billing/modules/subscription/features/panel.ts` | `billing::subscription` | `features` | `panel.ts`          |
| `src/modules/billing/api/x.ts`                               | `billing`               | `@unknown` | `api/x.ts`          |
| `src/modules/billing/modules/foo.ts`                         | `billing`               | `@unknown` | `modules/foo.ts`    |
| `src/modules/x.ts`                                           | `@root`                 | `@unknown` | `modules/x.ts`      |

### Вывод и границы

Текстовый `inspect` содержит `file`, `alias`, `module`, `layer`, `innerPath`. В JSON добавляются
поля `module`, `layer`, `innerPath`; существующий `alias: null` при отсутствии алиаса сохраняется. В
текстовом выводе отсутствие алиаса по-прежнему заменяется виртуальным путем. Ошибки выводятся через
существующий механизм CLI с кодом 1, в том числе при `--json`.

CLI сохраняет выбор опций первого правила `weld/*` с объектом опций. Если другое правило
переопределяет схему, `inspect` может показать другую схему; если первое правило не задает ее, а в
`settings.weld.layers` она отсутствует, команда завершится ошибкой. Ограничение документируется и
проверяется интеграционным тестом.

Приватные имена слоев и обработка `internal/` как контейнера приватных модулей отложены. При текущем
разборе `modules/foo/modules/internal/bar/...` определяется модуль `foo::internal`; это ограничение
расходится с описанием приватных модулей и требует отдельной работы.

## После завершения

Потребителям `weld inspect` потребуется добавить схему `layers` в конфигурацию для файлов, которые
они инспектируют. Поддержка приватных имен слоев и контейнера `internal/` требует отдельного
проектирования.
