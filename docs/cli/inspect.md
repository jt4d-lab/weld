# `weld inspect <file>`

Печатает путь файла и путь, которым файл записывается в импорте по алиасу:

```
$ weld inspect src/feature/internal.ts
file:  src/feature/internal.ts
alias: @/feature/internal.ts
```

- `file` печатается от корня репозитория: корень зависит от места запуска, а вывод — нет.
- Файл точки входа схлопывается в директорию: `src/feature/index.ts` печатается как `@/feature`.
  Если у ключа алиаса есть собственный хвост (`@/feature/* → src/feature/*`), голый `@/feature`
  такой записью не резолвится, поэтому печатается `@/feature/index.ts`.
- Точный ключ без хвоста (`@/config → src/config`) уже сам является специфаером:
  `src/config/index.ts` печатается как `@/config`, и имя файла к нему не дописывается —
  `@/config/index.ts` такой записью не резолвится.
- Точный ключ не выражает путь ниже своего якоря (`@/config/other.ts` при якоре `src/config`
  TypeScript не находит), поэтому такой файл печатается специфаером более широкого звездного алиаса
  — `@/config/other.ts` при `@/* → src/*`; если звездного алиаса нет, печатается виртуальный путь,
  как и для непокрытого файла.
- Если файл лежит прямо в директории алиаса с хвостом в ключе, хвостом становится имя файла:
  `src/index.ts` при алиасе `@/* → src/*` печатается как `@/index.ts` — голый `@` таким импортом не
  резолвится.
- Если файл не покрывает ни один алиас, в `alias` печатается виртуальный путь от корня репозитория
  (`/src/feature/internal.ts`), а не относительный путь. `index.<ext>` в корне репозитория схлопнуть
  некуда: печатается `/index.ts`, а не `/`.
- Директория аргументом не принимается: команда спрашивает про конкретный файл.

## `--json`

```
$ weld inspect --json src/feature/internal.ts
{
  "file": "src/feature/internal.ts",
  "alias": "@/feature/internal.ts"
}
```

- `file` повторяет строку `file:` текстового вывода.
- `alias` равен `null`, если файл не покрыт ни одним алиасом; в текстовом режиме на этом месте
  печатается виртуальный путь.
