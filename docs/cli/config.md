# `weld config <path>`

Печатает файл (или сэмпл директории) и разобранные настройки `settings.weld`:

```
$ weld config src/feature/internal.ts
file:   src/feature/internal.ts
config: eslint.config.js
settings.weld:
  repoRoot:       /home/user/project
  aliasesBaseUrl: .
  tsconfig:       tsconfig.json
  aliases:
    @/* → /src/*
```

Директория заменяется сэмплом — первым файлом, которому конфиг задает настройки WELD:

```
$ weld config src/feature
file:   src/feature/index.ts (sample of src/feature)
config: eslint.config.js
settings.weld:
  repoRoot:       /home/user/project
  aliasesBaseUrl: .
  tsconfig:       tsconfig.json
  aliases:
    @/* → /src/*
```

- `file` и `config` печатаются от корня репозитория; конфиг вне корня (через `--config` или
  найденный выше `.git`) — абсолютным путем: относительного пути от корня для него не существует.
- `config` — примененный ESLint-конфиг. Когда конфигов в проекте несколько, эта строка и есть ответ
  на вопрос, откуда взялись напечатанные настройки.
- Обход идет вглубь, а записи каждой директории перебираются по алфавиту; `node_modules` и скрытые
  директории пропускаются.
- Сэмплом становится первый файл с модульным расширением, которому примененный конфиг задает
  настройки WELD: игнорируемые файлы пропускаются, а файл, к которому конфиг ничего не добавляет
  (вне шаблонов `files` и без глобального слоя), сэмплом не считается. Сверх того, файл без
  `settings.weld` и без опций правил `weld/*` уступает любому файлу, которому они достаются: поэтому
  `jest.config.js` или `next.config.mjs` из корня проекта сэмплом не станут, даже если сортируются
  раньше `src/`, — глобальный слой конфига (`weld.configs.recommended`, общий `{ rules }`) делает
  непустым конфиг любого линтуемого файла, но настроек WELD ему не передает. Если настроек WELD в
  конфиге нет вовсе, сэмплом становится первый годный файл. Файл с именем `eslint.config.*` сэмплом
  не становится никогда: он тоже линтуемый, но настроек директории не представляет.
- В директорию с собственным `eslint.config.*` обход не заходит: файлы там описывает этот конфиг, а
  конфиг команды выбран по пути аргумента, так что пара `file:`/`config:` описывала бы разные
  конфиги одного файла — прямой запрос `weld config <файл>` ответил бы другим `config:` и другими
  настройками. Поэтому `weld config packages` в монорепе с пакетными конфигами отвечает ошибкой
  `no lintable files in packages`: файлов под выбранным конфигом в этой директории нет. С `--config`
  границы нет — указанный конфиг применяется к любому пути под текущей директорией.
- `repoRoot` — действующий корень репозитория, а не значение из конфига: при автопоиске он
  поднимается до якорей алиасов из tsconfig.
- `aliasesBaseUrl` и `tsconfig` печатаются как заданы в конфиге или в опциях правила (или их
  значения по умолчанию).
- Пометок происхождения значения нет: отличить `repoRoot` из конфига от найденного автоматически по
  выводу нельзя.
- Алиасов нет — печатается `  aliases: (none)`.
- Запись алиаса печатается в форме `tsconfig`: `<prefix>/* → <anchor>/*`, а у точного ключа хвоста
  `/*` нет ни с одной стороны (`@/config → /src/config`).
- Обход директории ограничен: 5000 записей — предел просмотра. Если годный файл к этому моменту
  найден, команда возвращает его, а не ошибку: предел ограничивает работу, а не уже полученный
  ответ. Ошибка `no lintable files … (stopped after 5000 entries)` появляется, только когда ответа
  нет.

## `--json`

```
$ weld config --json src/feature
{
  "file": "src/feature/index.ts",
  "configFile": "eslint.config.js",
  "sampleOf": "src/feature",
  "settings": {
    "repoRoot": "/home/user/project",
    "aliasesBaseUrl": ".",
    "tsconfig": "tsconfig.json",
    "aliases": [
      {
        "prefix": "@",
        "anchor": "/src",
        "star": true
      }
    ]
  }
}
```

- `file` и `configFile` в JSON повторяют строки `file:` и `config:` текстового вывода, включая
  абсолютный путь у конфига вне корня. `settings.repoRoot` остается абсолютным: по нему эти пути и
  разрешаются.
- `star` у записи алиаса — форма ключа из `paths`: `true` у `@/* → src/*`, `false` у точного
  `@/config → src/config`.
- `sampleOf` есть только у директории и повторяет аргумент в том виде, как его ввели.
