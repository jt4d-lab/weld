# CLI

Пакет ставит рядом с плагином исполняемый файл `weld`. Он показывает эффективную конфигурацию WELD
для файла или директории — ту же, которую видит правило при линте: `settings.weld` плюс найденный
корень репозитория.

Отдельного конфига у CLI нет. Он читает эффективный ESLint-конфиг проекта, поэтому настройки
приходят из того же источника, что у правила, с тем же приоритетом (опции правила → `settings.weld`
→ автопоиск в tsconfig). Опции берутся из того же конфига: если проект настраивает WELD не в
`settings.weld`, а в опциях правила `weld/*`, CLI видит их так же, как правило. Если правил `weld/*`
с опциями несколько, CLI берет первое по порядку конфига: напечатать один ответ сразу за все правила
нельзя, а разные опции у правил одного пакета — редкость.

Оговорка одна: `repoRoot` и пакет `eslint` берутся от текущей директории, а ESLint-конфиг — от пути
аргумента. Поэтому запускать команды стоит из корня проекта: тогда `repoRoot` совпадает с тем, что
увидит правило, запущенное оттуда же. Конфиг же CLI выбирает по пути аргумента, поэтому при
вложенных пакетных конфигах его ответ совпадает с ESLint 10 или с ESLint, запущенным из директории
пакета, но не с ESLint 9, запущенным из корня: тот ищет конфиг только от текущей директории.

## Требования

- Node 20.19+;
- ESLint 9 или 10, установленный в самом проекте: CLI загружает пакет `eslint` из `node_modules`
  проекта, чтобы прочитать его конфиг.

Относительные аргументы отсчитываются от текущей директории, а не от корня репозитория. От нее же
ищется пакет `eslint` и корень репозитория, поэтому директория запуска влияет на ответ: запускать
команды из корня проекта.

```sh
npx weld config src/feature
yarn weld config src/feature
```

## Выбор ESLint-конфига

Конфиг выбирается по пути аргумента, а не по текущей директории: вверх от директории цели ищется
ближайший `eslint.config.*`, и первый найденный выигрывает у более далекого. У файла обход
начинается с его директории, у директории — с нее самой, поэтому для директории конфиг выбирается по
самому пути, а сэмпл остается лишь представительским файлом. Обход идет до корня файловой системы:
конфиг, лежащий выше `.git`, тоже будет найден и применен.

Внутри одной директории имя выбирается в порядке `eslint.config.js`, `.mjs`, `.cjs`, `.ts`, `.mts`,
`.cts` — том же, в котором ищет ESLint 10.

Шаблоны `files` и `ignores` найденного конфига считаются от его директории — тот же `basePath`,
который вычислил бы сам ESLint. Поэтому пакетный конфиг монорепа действует на файлы пакета, а не на
весь репозиторий.

Поиск свой, а не на стороне ESLint: на 9.x ESLint ищет конфиг только от текущей директории, на 10.x
— от самого файла, и ответ CLI не должен зависеть от того, какую версию поставили. Корень
репозитория (`repoRoot`) при этом по-прежнему ищется от текущей директории: путь аргумента влияет
только на выбор конфига.

Имя `eslint.config.ts` (как и `.mts`/`.cts`) входит в поиск, но загрузить такой файл может не каждая
связка версий:

- ESLint 10 грузит TS-конфиг через `jiti`. Это необязательный peer-пакет ESLint, в его поставку не
  входящий: без установленного `jiti` CLI называет причину и предлагает поставить его или указать
  `--config` на JS-конфиг.
- ESLint 9 таких имён не ищет и грузит конфиг нативным `import()`, поэтому всё решает Node: на Node
  22.18+ (и 24) типы срезаются нативно и конфиг читается, а на более старых Node CLI объясняет, что
  импортировать TypeScript нечем, и предлагает `--config` с JS-конфигом. Флаг ESLint
  `unstable_ts_config`, которым ESLint 9 включает `jiti`, через `weld` не пробрасывается.

## `--config <path>`

Глобальный флаг: отменяет поиск ближайшего конфига и применяет указанный — работает как
`eslint --config`. Путь резолвится от текущей директории, шаблоны `files`/`ignores` считаются от нее
же. Директория конфига при этом роли не играет: файл под текущей директорией получает настройки
указанного конфига, даже если лежит выше или в стороне от него.

А вот путь вне текущей директории конфиг не покрывает вовсе — команда говорит об этом прямо, а не
сообщает, что файл игнорируется: игнор здесь не причина, а следствие.

```sh
weld config --config eslint.config.ci.mjs src/feature
```

Отсутствующий путь и существующий путь, который файлом не является (директория, FIFO, сокет), — две
разные ошибки: `config path does not exist: <path>` и `config path is not a file: <path>`. Обе дают
код `1`.

## Цвета

По умолчанию подписи приглушенные, а значение алиаса — акцентное. Цвет выключается флагом
`--no-color` и переменной `NO_COLOR`, а `FORCE_COLOR` его, наоборот, включает; в выводе не в
терминал цвета выключены сами. `--no-color` сильнее переменных окружения.

```sh
weld config --no-color src/feature
```

## `--json`

Глобальный флаг программы: печатается только JSON, без подписей и цветов. Состав полей у каждой
команды свой и описан вместе с ее текстовым выводом.

## Коды возврата и ошибки

Успех — код `0`. Любая ошибка — код `1`.

В текстовом режиме сообщение уходит в stderr как `error: <текст>`:

```
$ weld config src/missing
error: path does not exist: src/missing
```

С `--json` ошибка печатается в stdout в той же машиночитаемой форме, чтобы потребителю не пришлось
разбирать текст. Это касается и ошибок использования (пропущенный аргумент, неизвестная команда,
запуск без команды): они тоже уходят в stdout как JSON и дают код `1`, а не текст в stderr.

```
$ weld config --json src/missing
{
  "error": "path does not exist: src/missing"
}
```

Возможные сообщения:

| сообщение                                                                                     | когда                                                    |
| --------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| `eslint is not installed in this project`                                                     | в проекте нет пакета `eslint`                            |
| `eslint could not be resolved from <cwd>`                                                     | пакет есть, но его точку входа не удалось найти          |
| `eslint could not be loaded from <cwd>`                                                       | пакет есть, но не загружается                            |
| `path does not exist: <path>`                                                                 | аргумент не существует                                   |
| `cannot read <path>`                                                                          | путь есть, но файловая система отвечает ошибкой          |
| `no eslint config found for <path>`                                                           | ни здесь, ни выше нет конфига с именем из списка         |
| `config path does not exist: <path>`                                                          | `--config` указал на отсутствующий путь                  |
| `config path is not a file: <path>`                                                           | `--config` указал на существующий путь, который не файл  |
| `<path> is outside the config base directory: …`                                              | `--config` и путь вне текущей директории                 |
| `eslint config <path> is a TypeScript file and this Node.js version cannot import it: …`      | ESLint 9 на Node без нативной поддержки TS               |
| `eslint config <path> is a TypeScript file and ESLint needs the 'jiti' library to load it: …` | ESLint 10 без установленного `jiti`                      |
| `eslint ignores <path>`                                                                       | файл игнорируется конфигом                               |
| `no lintable files in <path>`                                                                 | в директории нет файла, который линтер обрабатывает      |
| `expected a file, got a directory: <path>`                                                    | `inspect` получил директорию                             |
| `missing command`                                                                             | команда не указана (справка при этом печатается)         |
| `<file> is outside the repository root`                                                       | путь вне корня репозитория, виртуального пути у него нет |

`--version` печатает версию пакета из его `package.json`, `--help` — список команд и флагов.
