# Модули

Модуль — это самостоятельная, логически связанная часть программы, отвечающая за конкретную
функциональную область.

Модуль в WELD позволяет собирать код домена в одном месте, предоставляя доступ к API через одну или
несколько точек входа. Несколько точек входа позволяют сохранить единый модуль как функциональную
область, при этом предоставляя API, которые относятся к разным слоям.

## Какую проблему решает

Модули и слои — разные оси архитектуры:

- **Модуль** объединяет код одной функциональной области
- **Слои** задают порядок зависимостей между частями приложения

Разделение по этим осям позволяет одновременно держать весь код домена рядом и контролировать
зависимости между слоями, не требуя, чтобы каждый модуль был полностью независим от остальных.

**Пример**

Рассмотрим два модуля: `auth`, отвечающий за текущую сессию пользователя, и `users`, содержащий
компоненты для работы с пользователями.

Модуль `auth` предоставляет виджет управления текущей сессией и хук для получения данных текущего
пользователя. Модуль `users` содержит список пользователей и компонент аватара.

```mermaid
treeView-beta
src/
  auth/ icon(module)            ## модуль аутентификации
    widgets/ icon(widgets)
      ProfileMenu               ## виджет управления текущей сессией
    entities/ icon(entities)
      useCurrentUser            ## хук для получения данных текущего пользователя
  users/ icon(module)           ## модуль пользователей
    widgets/ icon(widgets)
      UsersList                 ## список пользователей
    entities/ icon(entities)
      UserAvatar                ## аватар пользователя
```

Компонент `ProfileMenu` должен отображать аватар текущего пользователя, поэтому ему нужен
`UserAvatar` из модуля `users`. В свою очередь, `UsersList` может использовать `useCurrentUser`,
чтобы выделять текущего пользователя в списке.

Таким образом, `auth` зависит от части `users`, а `users` — от части `auth`.

Если рассматривать только зависимости между модулями, возникает цикл зависимостей. Однако на уровне
слоев зависимости направлены в одну сторону: `widgets` могут использовать `entities`, но не
наоборот.

## Слои модулей и слои приложения

Состав слоев — часть архитектуры конкретного проекта. WELD не навязывает универсальный набор: проект
сам определяет, какие слои ему нужны и в каком порядке они располагаются.

Для описания архитектуры используются два списка:

- `layers` задает слои приложения
- `moduleLayers` задает слои модулей

**Например,** конфигурация:

`layers: common, @modules, pages, app` <br/>`moduleLayers: entities, widgets`

задает следующий порядок слоев:

<div align="center">

```mermaid
flowchart TB
    app --> pages --> widgets --> entities --> common

    subgraph modules["@modules"]
        direction TB

        widgets
        entities
    end
```

</div>

Маркер `@modules` обозначает место, в котором располагаются слои модулей. Поэтому `entities` и
`widgets` становятся частью общей архитектуры приложения, а не отдельной системой слоев,
существующей независимо от нее.

Такой подход позволяет сочетать доменную организацию кода с единым порядком слоев.

## Модуль с одной точкой входа

Модуль с одной точкой входа имеет корневой баррель, и другие модули имеют права обращаться к нему
только через этот баррель

Пример такого модуля:

```mermaid
treeView-beta
src/ icon(src)
  modules/
    calculations/ icon(module)
      index.ts
```

:::warning Важно!

Взаимодействие дочерних модулей с родительскими описано в статье
[Вложенные модули](./nested-modules.md)

:::

## Модуль с несколькими точками входа

У такого модуля нет корневого барреля: точками входа служат все его **непосредственные** файлы и
каталоги. Другие модули могут обращаться к нужно точке входа, не импортируя лишнего.

Пример такого модуля:

```mermaid
treeView-beta
src/ icon(src)
  modules/
    users/ icon(module)
      routes.ts  ## Точка входа
      entities/
        index.ts ## Точка входа
      widgets/
        index.ts ## Точка входа
        nice-widget.ts icon(private) ## Не может быть точкой входа
      utils/
        index.ts  ## Точка входа
```

> Файл `users/widgets/nice-widget.ts`, не является корректной точкой входа, т.к. вложенные
> директории и файлы не могут быть точками входа в модуль.

## Слои внутри модуля

Принадлежность к слою задает первое имя на пути от корня модуля. Если это имя совпадает с именем
слоя из `moduleLayers`, вся ветка модуля с этим именем относится к слою — целиком, на любой глубине
внутри нее. Глубже слой не ищется: имена внутри ветки принадлежность не меняют.

> При `moduleLayers: entities, widgets` в примере выше, директория `users/widgets` и все ее
> содержимое относится к слою `widgets`, а директория `users/entities` - к слою `entities`.
>
> Даже если внутри `widgets` появится директория `entities`, она останется частью `widgets`: слой
> задается один раз, у входа в ветку.

Ветки модуля, чье имя не совпадает ни с одним слоем, не относятся ни к одному слою и стоят ниже всех
слоев модуля.

<div align="center">

```mermaid
flowchart TB
    app --> pages --> widgets --> entities --> custom --> common

    subgraph modules["@modules"]
        direction TB

        widgets
        entities
        custom["`_все остальное_`"]
    end
```

</div>

## Правила

1. **Модуль с центральной точкой входа имеет корневой баррель**

    Если модуль предоставляет центральную точку входа, он должен иметь корневой `index.ts`, который
    и определяет публичный API. Внешние модули не должны обращаться к внутренним файлам такого
    модуля в обход барреля.

2. **Модуль с несколькими точками входа не имеет корневого барреля**

    В этом случае точками входа становятся каталоги и файлы непосредственно внутри модуля. Каждый из
    них предоставляет отдельный интерфейс для потребителей.

3. **Слой задает имя ветки модуля**

    Код относится к слою, если первое имя на пути от корня модуля совпадает с именем слоя из
    `moduleLayers`. Слой распространяется на всю ветку, а вложенные имена его не переопределяют.

4. **Ветки без слоя - ниже всех слоев модуля**

    Ветки модуля, чье имя не совпадает ни с одним слоем из `moduleLayers`, не относятся ни к одному
    слою и стоят ниже всех слоев модуля.

5. **Модуль с центральной точкой входа ниже всех слоев модуля**

    Такой модуль не может импортировать другие модули, но любой слой внешних модулей может его
    импортировать.
