# Баррель как public API

## Определение

Баррель выступает единственной точкой входа в директорию, формируя её публичный API для всего, что
находится внутри.

## Какую проблему решает

Без чёткой границы потребители импортируют внутренние файлы напрямую, превращая детали реализации в
публичный контракт — и любой рефакторинг внутри сущности начинает ломать весь проект.

## Правила

**Явный интерфейс, а не зеркало**

Баррель должен содержать явный список именованных реэкспортов. Использование `export * from './...'`
запрещено. Оно превращает границу в автоматическое зеркало, где любой внутренний export случайно
становится публичным контрактом.

**Разделение потоков импортов**

**Снаружи:** Внешний код импортирует сущность строго через её баррель.

**Внутри:** Файлы внутри сущности импортируют друг друга напрямую, минуя собственный `index.ts` —
это спасает от циклических зависимостей.

**Осознанное расширение API**

Каждая строка в барреле — это публичное обещание поддерживать имя. Добавлять экспорт нужно только
тогда, когда он действительно нужен потребителям сегодня. Экспортировать «на будущее» или «всё, что
лежит в папке» создаёт ненужные обязательства.

## Почему

Соблюдение этих правил превращает баррель из просто файла с экспортами в полноценный инструмент
архитектурного контроля. Вот что это даёт на практике:

**Прозрачность на ревью**

Расширение публичного API — это правка одной строки в одном файле. Ревьюер сразу видит, что контракт
изменился. Это исключает ситуации, когда новый export тихо появляется где-то в глубине сущности и
незаметно расширяет публичную поверхность.

**Безопасный рефакторинг**

Пока баррель не меняется, внутри сущности можно свободно переставлять файлы, переименовывать
внутренние хуки и делить модель на части. Внешний код этого не заметит.

## Good example

```ts
// src/modules/order/entities/index.ts
export { OrderCard } from './ui/order-card';
export type { Order, OrderStatus } from './model/types';
```

```ts
// src/modules/order/entities/ui/order-card.ts
import { type Order } from '../model/types';
```

Внутренние импорты - только относительные

```ts
// src/pages/order/order-page.tsx
import { OrderCard, type Order } from '@/modules/order/entities';
```

Потребитель зависит от контракта

## Bad example

```ts
// src/modules/order/entities/index.ts
export * from './ui/order-card';
export * from './model/types';
```

Экспорт всего

Внутренние импорты - только относительные

```ts
// src/modules/order/entities/ui/order-card.ts
import { type Order } from '..';
```

Импорт своего же барреля - вероятность циклических ссылок

```ts
// src/pages/order/order-page.tsx
import { OrderCard } from '@/modules/order/entities/ui/order-card';
```

Потребитель импортирует в обход публичного API

## Исключения

- Реэкспорт всего из вложенного барреля может быть оправдан
