# Слои: внутреннее представление

Плагин работает с единым внутренним списком слоёв, который формируется из двух настроек — `layers` и
`moduleLayers`. Направление зависимостей считается по позиции в этом списке: слой может
импортировать только те слои, что стоят левее него.

## Входные настройки

Настройки задаются в секции `settings.weld` (как и остальные настройки плагина; одноимённые опции
правила перекрывают значения секции).

| настройка      | формат                          | что означает                           |
| -------------- | ------------------------------- | -------------------------------------- |
| `layers`       | непустой список имён            | слои корня проекта + маркер `@modules` |
| `moduleLayers` | список имён (может быть пустым) | слои, которые живут внутри модуля      |

### Маркер `@modules`

`@modules` — зарезервированный токен в списке `layers`. Он отмечает позицию, на которую
разворачиваются слои из `moduleLayers`.

- маркер **обязателен**;
- встречается **ровно один раз**;
- имя, начинающееся с `@`, не допускается — `@` зарезервировано под маркер.

Пример:

```js
{
    settings: {
        weld: {
            layers: ['shared', '@modules', 'pages', 'app'],
            moduleLayers: ['entities', 'widgets'],
        },
    },
}
```

## Построение внутреннего списка

Из исходных настроек формируется внутренний список, с которым уже и работают правила. Каждое имя в
`layers` попадает в список с префиксом `root:`; маркер `@modules` на своём месте заменяется именами
из `moduleLayers` (в исходном порядке), каждое с префиксом `module:`.

Результат — **один глобальный массив**, одинаковый для всех линтуемых файлов проекта. От конкретного
файла или модуля список не зависит.

### Пример

Вход:

```
layers: shared, @modules, pages, app
moduleLayers: entities, widgets
```

Внутренний список:

```
root:shared, module:entities, module:widgets, root:pages, root:app
```

`shared` → `root:shared`; `@modules` развернулся в `module:entities, module:widgets`; `pages` и
`app` → `root:pages, root:app`.

### Граничные случаи

| ситуация                                                      | результат                                                                         |
| ------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| `moduleLayers` пуст                                           | маркер `@modules` разворачивается в ничего — во внутреннем списке только `root:*` |
| имя есть и в `layers`, и в `moduleLayers` (например, `pages`) | два разных элемента: `module:pages` и `root:pages` — они не совпадают             |
| `layers` состоит только из `@modules`                         | во внутреннем списке только `module:*`                                            |

### Направление

Правило направления: **импорт разрешён только влево** — слой может зависеть только от элементов,
стоящих левее него во внутреннем списке; элементы правее от него недоступны.

На примере выше:

```
root:shared   module:entities   module:widgets   root:pages   root:app
```

| элемент           | может импортировать                                |
| ----------------- | -------------------------------------------------- |
| `root:shared`     | ничего (слева пусто)                               |
| `module:entities` | `root:shared`                                      |
| `module:widgets`  | `root:shared`, `module:entities`                   |
| `root:pages`      | `root:shared`, `module:entities`, `module:widgets` |
| `root:app`        | все элементы, стоящие левее                        |

Из этого следует: `pages` видит `shared` и оба `module:*`; `shared` никого не видит;
`module:entities` видит `root:shared`, но не видит `root:pages` — тот правее.
